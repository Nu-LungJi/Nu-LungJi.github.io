### 개요
**OOP(Object-Oriented Programming)"객체 지향 프로그래밍"** 은 객체들이 서로 상호작용을 통해 동작하도록 프로그램을 설계하는 프로그래밍 패러다임이다.

여기서 "객체(Object)"라는 것은 속성(필드)과 동작(메서드)로 구성된 클래스의 인스턴스이다. 객체는 

OOP에는 4 가지의 주요한 특징을 가지고 있는데, [추상화], [캡슐화], [다형성], [상속] 으로 이뤄져있다.

### 장점
- 다른 클래스를 가져와서 사용할 수 있어 재사용성에서 강점을 보임.
- 객체 단위로 코드가 나눠져 있어, 디버깅과 유지보수가 용이함.
- 클래스 단위로 모듈화가 가능하여, 대규모 프로젝트에 적합하다.

### 단점
- 설계가 복잡하여, 성공적으로 설계된 프로그램을 만들려면, 많은 시간을 쓰게 된다.
- 객체가 많아질수록 프로그램의 메모리가 커지고, 속도가 느려진다.
### 객체 지향 VS 절차 지향 VS 데이터 지향

프로그래밍 방법론에서 OOP에서 같이 언급되는 두 가지 방법론이 **"절차 지향 - PP(Procedural Programming)"**, **"데이터 지향 - DOP(Data-Oriented Programming)"** 이다. 이 3 가지의 방법론은 서로 추구하는 바가 다른데, 

우선 절차 지향 부터 알아보자, 절차 지향 프로그래밍은 프로그램을 순차적으로 진행하는 '절차'로 구성하는 프로그래밍 방식이고,

데이터 지향은 프로그램의 구조를 객체가 아닌, "데이터를 어떻게 효율적으로 배치하고 처리할 것인지" 라는 생각에서 고안된 프로그래밍 방식이다.

### 가상 함수 (Virtual Function)

→ **가상 함수 포인터/테이블 :** 클래스에 가상 함수를 만들게 되면, 자동적으로 **[가상 함수 포인터(vptr)]와 [가상 함수 테이블(vtbl)]** 이 생성된다. 이 둘은 가상 함수를 작동 시키기 위해서 존재하는 요소이다.

→ **작동 방식 :** 컴파일 시점에 가상 함수 테이블/포인터가 생성되고, 객체가 소유한 가상 함수 포인터로 가상 함수 테이블에 접근해서, 함수를 호출.

→ **[가상 함수 테이블]** : 가상 함수 이름들을 정리해 놓은 목록 파일. 
(함수의 주소를 저장해두기 위함.) (클래스 크기에 영향을 끼치지 않음.)

→ **[가상 함수 포인터] :** 가상 함수를 호출하기 위한 포인터(객체가 직접 호출 불가)
(일반 멤버 함수보다 느린 속도.) (클래스 크기에 영향을 끼침 : 8byte)

→ 필요한가? : 일반 멤버 함수보다 느리며, 크기를 많이 차지하기에 비효율적인 문법일 수 있으나, ”다형성”이란 문법을 쓰기 위해서는 “감안” 하면서 사용해야 하는 문법이다. (장점이 크기에)
