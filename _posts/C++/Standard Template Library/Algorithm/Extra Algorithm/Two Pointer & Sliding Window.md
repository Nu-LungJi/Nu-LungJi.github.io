Q. N개의 데이터들 중에서 2개를 뽑아 합이 M이 되는 경우의 수를 찾는 문제. 에서 Brute-Force 방식의 완전 탐색을 하게 되면, 2중 for문으로 풀고, 이는 O(N<sup>2</sup>)의 시간 복잡도로 해결이 된다. 다만 이건 시간이 너무 걸리게 되므로, 백트래킹으로 풀이도 가능하지만, '투포인터' 방식도 가능하다.

→ **투 포인터 :** 연속된 데이터들에서 두 개의 포인터를 사용하여 문제를 해결하는 탐색 방법의 최적화 테크닉이다. Brute-Force의 O(N<sup>2</sup>) 시간 복잡도를 '단 한 번의 반복으로' O(N)으로 풀이가 가능하게 만들어, 더 빠른 시간에 풀이가 가능하게 만든다.

→ **과정**
1. 처음은 Start(시작 PTR), End(끝 PTR) 두 개의 포인터를 준비하고, 두 포인터가 배열의 맨 처음 원소를 가리킨다. (문제에 따라 Start는 처음 원소, End는 끝 원소로 시작 하기도 한다.)
2. 포인터를 이동시키면서 경우의 수를 따져보고, 합이 큰 경우 Start를 옮겨 기존의 합에서 차감시키고, 합이 작은 경우 End를 옮겨 값을 추가로 더해준다. 
3. 적합한 경우의 수를 찾아 값을 도출한다.

→ **문제 전략 :** 문제가 두 가지로 나뉠 수가 있다.
1. N개 데이터의 배열에서 <strong><u>2개를 뽑아 합이 M</u></strong>(이상/이하)이 되는 경우 구하기.
2. N개의 데이터 배열에서 <strong><u>연속되는 구간의 합이 M</u></strong>(이상/이하)이 되는 경우 구하기.

1번째 문제는 '정렬'을 먼저 해주는게 좋다. 그리고 포인터는 Start는 첫 원소, End는 끝 원소로 두어, 끝 원소 기준으로 옮기는게 좋다. (끝 원소가 제일 큰 값이 되므로, 합이 M을 넘어가면, End를 앞으로 이동시켜, 값을 줄이고, M을 넘지 않으면 Start를 이동시켜, 값을 키우는 방식의 전략)

2번째 문제는 두 포인터를 첫 원소에 두어 시작하고, End포인터를 계속 옮기다가 합이 M을 넘어가면, Start를 이동시켜 구간 합에서 Start를 빼주면서 합을 조절하는 방식의 전략.
