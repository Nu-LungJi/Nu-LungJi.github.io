
**Dangling Pointer :** 포인터 변수가 이미 해제된 메모리 주소를 가리키는 경우 해당 포인터를 '댕글링 포인터'라고 합니다. 이는 <해제 후에 초기화 부재> 또는 <소멸된 지역 변수 참조>하는 경우에 발생하는데, 이는 가끔씩 '정상적인 동작'을 하는 경우가 있어, 디버깅을 어렵게하고, 데이터를 손상시키는 경우를 가져오기도 합니다. 그렇기에, 해제 후에 nullptr로 초기화 해주고, 유효한 포인터인지 확인 해주는 것이 안전합니다.

**Shallow Copy / Deep Copy :** 깊은 복사는 새로운 메모리를 차지하여 데이터를 복사하는 방식입니다. 데이터가 완전히 독립적이지만, 메모리를 차지하는 '자원 소모'의 단점을 가집니다. 반면에 얕은 복사는 주소를 복사하여 같은 메모리 공간을 가리키게 하는 복사 방식입니다. 메모리 차지에 부담이 없지만, 복사한 객체/변수의 데이터가 변경되면 원본 또한 변경되는 위험이 있습니다.

**Garbage Collection :** 프로그램에서 동적 할당 했던 메모리 영역 중 더 이상 참조되지 않아 사용할 필요가 없는 메모리를 모아 자동으로 탐지하고 회수하는 메모리 관리 기법입니다. 메모리 관리가 편하고, 메모리 누수나 Dangling Pointer 위험을 줄일 수 있지만, CPU 비용이나 일시적인 지연이 발생할 수 있습니다.

### OS

**Q. Context Switching에 대해 설명해주세요.**
A. 하나의 프로세스가 CPU를 사용 중인 상태에서 다른 프로세스가 CPU를 사용하도록 하기 위해, 이전 프로세스의 상태를 보관하고, 새로운 프로세스 상태를 복원하는 과정을 말합니다.

Q. **프로세스와 스레드의 차이**
A. 프로세스는 OS로부터 할당 받은 메모리 상에서 실행되고 있는 프로그램의 인스턴스를 말합니다. 그리고 스레드는 하나의 프로세스가 할당 받은 자원을 이용하는 여러 실행 흐름의 단위입니다. 프로세스는 독립적인 자원을 할당 받아 사용하고, 스레드는 Heap, Data, Code 영역은 다른 스레드와 공유하되, Stack영역은 독립적으로 갖는 메모리 구조적 차이가 있습니다. 또한 프로세스는 각각 개별적으로 실행되고 있기에 하나의 프로세스가 종료되어도 다른 프로세스에 영향을 상대적으로 적게 주고, 스레드는 하나의 스레드가 치명적인 오류를 발생시키면, 프로세스 전체를 종료시킬 수 있다는 의존성 차이도 있습니다.

**EQ1. 스레드가 스택 영역만 개별적으로 갖는가?**
EA1. 스레드는 Stack영역 뿐만 아니라, CPU Register Context, Program Counter를 개별적으로 가집니다. + Register Context, PC는 서로 다른 명령어 위치에서 실행되고, 실행 상태를 보존해야 하기 때문에, RC와 PC를 따로 가집니다.

**EQ2. 프로세스보다 스레드를 사용하는 장점 / 멀티 프로세스보다 멀티 스레드를 사용하는 이유**
EA2. 자원을 새로 할당 받아 프로세스를 생성하면 상당한 메모리를 차지하게 되는 반면에 기존 프로세스의 Code, Data, Heap 등의 자원을 공유하기 때문에 스레드 생성이 생성 비용과 자원 관리 측면에서 유리합니다. 그리고 프로세스는 서로 다른 메모리 공간을 사용하기에 IPC를 통해 통신해야 하지만, 같은 프로세스의 스레드들은 메모리 공간을 공유하므로 통신 비용이 상대적으로 적고 데이터 교환이 빠르기에, 스레드/멀티스레드를 사용합니다.

**Q. 교착 상태(DeadLock)에 대해 설명해주세요.**
A. 둘 이상의 프로세스나 스레드가 서로가 가진 자원을 획득하기 위해 대기하면서, 작업이 진행되지 못하고 정체되어 있는 상태를 말합니다. 교착 상태는 4가지 요인을 모두 만족할 때 발생을 합니다. 
첫 번째로 - 한 번에 한 프로세스만 공유 자원을 사용할 수 있는 "상호 배제", 
두 번째로 - 접근 권한을 양보하지 않은 상태에서 다른 자원에 대한 접근 권한을 요구하는 "점유와 대기", 
세 번째로  이미 할당된 자원은 다른 프로세스가 사용할 수 없는 "비선점",
네 번째로 - 두 개 이상의 프로세스가 자원 접근을 기다리는데, 그 관계에 사이클이 존재하는 "순환 대기"

**EQ1. 교착 상태는 어떻게 해결하나요?**
EA1. 교착상태는 **예방**(4가지 중에 하나를 제거하는), **회피**(발생한 경우 회피하는), **발견**(시스템에 교착상태가 발생했는지 점검하는), **회복**(교착 상태를 검출한 후 해결한다)

**Q. 경쟁 상태(Race Condition)에 대해 설명해주세요.**
A. 둘 이상의 프로세스나 스레드가 공유 자원에 동시에 접근할 때, Context Switching이나 병렬 실행으로 인해서, 접근/실행 순서에 따라 결과가 달라지는 상황을 말합니다. 경쟁 상태가 발생하게 되면, 원하는 결과를 보장받을 수 없거나 메모리 손상을 가져오게 됩니다.

**EQ1. 경쟁 상태를 방지하기 위해서 무엇을 해야 하나요?**
EA1. 경쟁 상태를 방지하기 위해서는 뮤텍스나 세마포어, 원자적 연산 동기화 기법을 사용할 수 있습니다. 

**EQ2. 뮤텍스와 세마포어의 차이에 대해 설명해주세요.**
EA2. 뮤텍스는 임계 영역에 한 번에 하나의 스레드만 접근을 허용시켜 다른 스레드들에게 대기를 강제시키는 동기화 기법이고, 세마포어는 한 번에 접근할 수 있는 스레드 수를 제한시켜 리소스를 모두 사용중인 경우 다음 작업을 대기시키는 기법입니다.

++ 뮤텍스와 세마포어 소유권
A. 뮤텍스는 소유권 개념이 있어, 뮤텍스를 소유한 스레드가 lock과 unlock을 하는 방식으로 '누가 잠갔는지'를 중요시 하고, 세마포어는 카운터 값을 관리하기에 '몇 자리 남았는가'를 중요시 한다.

++ 원자적 연산
A. 특정 연산을 한 번에 수행하여, 다른 스레드의 개입을 막는 동기화 기법입니다. 간편하고 빠르다는 장점을 가지지만, 복잡한 연산보다 단순한 연산에 주로 사용됩니다.

**Q. 임계 영역(Critical Section)에 대해 설명해주세요.**
A. 둘 이상의 프로세스나 스레드가 공유 자원에 동시에 접근하는 코드 영역을 말합니다.

**Q. 외부 단편화와 내부 단편화에 대해 설명해주세요.**
A. 메모리의 빈 공간의 총합은 시스템이 요청한 크기보다는 크지만, 메모리의 공간들이 연속적이지 않고 흩어져있어 충분한 메모리를 할당하지 못하는 현상은 외부 단편화, 메모리를 할당할 때, 요청한 크기보다 더 큰 고정 블록을 할당하여, 메모리 블록 내부에 낭비되는 공간이 발생하는 현상을 내부 단편화라고 합니다.

**Q. 페이징에 대해 설명해주고, 장단점을 설명해보세요.**
A. 페이징 기법은 가상 메모리와 물리 메모리를 '페이지'와 '프레임'이라는 고정된 크기 블록으로 나눠 관리하는 메모리 관리 기법입니다. 프로그램을 잘게 나누어 비연속적인 공간에도 메모리를 배치할 수 있게 해줍니다. 외부 단편화를 완전히 해결하는 장점을 가지지만, 마지막 페이지의 남는 공간으로 인해 내부 단편화를 완전히 해결하지 못하는 단점이 있습니다.

### Data Structure

**Q. Big-O 표기법에 대해 설명해주세요.**
A. Big-O 표기법은 데이터 크기가 증가할 때 시간 복잡도와 공간 복잡도가 어떻게 증가하는지 상한으로 표현하여, 알고리즘의 효율성을 판단하기 위한 표기법입니다.

++ 최악의 상황
어떤 데이터가 들어와도 이보다 더 오래 걸리지 않는다는 것을 보장하기 위한 표기이기도 하다.

**Q. 배열과 링크드 리스트 차이점에 대해 설명해주세요.**
A. 배열은 메모리를 할당 받을 때, 연속적인 메모리 할당이 보장됩니다. 데이터를 접근할 때 Random Access접근으로 상수 시간 복잡도의 빠른 성능을 보여줍니다. 하지만 삽입과 삭제에서는 데이터를 중간에 삽입이나 삭제시에, 원소들을 뒤로 이동 시켜야 하므로, O(N)의 성능을 보입니다.
링크드 리스트는 메모리에 할당될 때, 흩어져서 저장이 됩니다. 연속적인 메모리가 아니므로 삽입/삭제할 노드의 위치만 알고 있다면 상수 시간 복잡도의 빠른 성능을 보여주지만, 검색시에는 순차 접근으로 탐색해야 하기에, O(N)의 시간이 필요합니다.

**Q. Stack과 Queue 차이점에 대해 설명해주세요.**
A. Stack은 한 쪽 끝에서만 데이터를 넣거나 뺄 수 있는 후입선출의 선형 자료구조입니다. Queue는 한 쪽에서는 데이터를 넣고, 다른 한 쪽에선 데이터를 뺄 수 있는 선입선출의 선형 자료구조입니다.

++ Deque
양 쪽 끝에서 데이터를 넣거나 뺄 수 있는 선형 자료구조

**Q. HashTable에 대해 설명해주세요.**
A. HashTable은 Key와 Value를 쌍으로 저장하는 자료구조로, Hash Function을 통해 Key가 인덱스로 반환이 되어 탐색, 삽입, 삭제에서 평균적으로 O(1) 성능을 보여줍니다.

++ 해시 충돌
A. 서로 다른 해시 키가 Hash Function을 통해 같은 인덱스로 변환되는 현상을 '해시 충돌'이라고 합니다. 

++ 해시 충돌 해결
A. 충돌한 버킷을 연결 리스트나 레드-블랙 트리로 확장하여 충돌이 난 버킷에 지속적으로 데이터를 넣을 수 있게 하는 "Separate Chaining"방식과, 해시테이블의 빈 공간을 탐색해서 사용하는 "Open Address"방식으로 해결합니다.

**Q. Tree와 그래프의 차이점에 대해 설명해주세요.**
A. 그래프는 노드와 노드를 잇는 간선으로 구성되어, 노드 간의 네트워크 관계를 표현하는 비선형 자료구조입니다. 트리는 그래프의 특수한 형태로, 부모 노드와 자식 노드의 계층적 관계를 표현합니다. 또한 트리는 모든 노드가 연결되어 있고, 비순환 그래프라는 점에서 그래프와 차이점을 가집니다.

++Tree 성능
탐색, 삽입, 삭제 모두 평균 **O(log n)** 성능
